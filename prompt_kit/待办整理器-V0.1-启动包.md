# 待办整理器 V0.1 启动包

> 配套方案：`docs/方案-待办整理器-v0.4.md`
> 用途：一次性把活派清楚 → 按验收收活。别分批提需求。

---

## 一、定案摘要

| 项 | 结论 |
|---|---|
| 定位 | **待办整理器**，不是日程表、不是课表 |
| 主设备 | 手机（电脑可选） |
| 形态 | Vite + React 纯静态，最后 Capacitor 打 APK |
| 数据 | 设备本地 IndexedDB（Dexie），无云无同步、不留同步字段 |
| 主视图 | **队列**（唯一入口），固定占用作为不可拖的行混在其中 |
| 可用时间 | **七个值 + 单日覆盖 + 系统建议**，不是一个数字 |
| 课表 | **不做**。七个值就是课表的降维版 |
| 长期视图 | 14 天负载条，V0.1.1 |

## 二、派活话术（整段复制，不要拆开提）

```
【任务】做一个自用的待办整理 App（V0.1）。单用户，手机优先，纯本地。
核心：随便输入一句话，系统自动整理成一条今天能执行的队列。
不是日历，不是课表——课表我另有软件，这里不管几点上课。

【栈】Vite + React + TypeScript + Tailwind；存储用 Dexie（IndexedDB）；
拖拽用 dnd-kit；不用 Next.js（无服务端），不用 SQLite（手机上无 Node）。
最后用 Capacitor 打包 APK，命令行构建，不依赖 Android Studio。

【两张表】
Task
  id, title, raw_input, status(todo/doing/done/deferred/dropped),
  is_fixed, start_at, end_at, repeat(none|weekly),     -- 固定占用（课/会/约）
  est_min, due_at,                                      -- 软任务
  importance(1-5), urgency_manual, manual_priority, quadrant,
  queue_rank, rank_reason, pinned,
  slot_source(ai|user), is_locked,                      -- 时间来源
  created_at, done_at
Settings
  day_capacity { 1:180, 2:120, 3:180, 4:120, 5:240, 6:480, 7:480 }  -- 周一..周日，分钟
  capacity_override { "2026-11-20": 60 }                            -- 单日覆盖
  work_start("08:00"), work_end("23:00"), buffer_min(10),
  prefs_json, ai_key
注意：不要为"将来的云同步"预留 user_id / updated_at / synced_at 等字段。

【可用时间：三层叠加，不是常数】
  可用(某天) = capacity_override[该天] ?? day_capacity[weekday(该天)]
  1) 设置页给四个预设按钮：[紧张 2h][正常 4h][宽裕 6h][全天 10h]
     一键套用到周一至周五，周六周日单独调。不要做 7 个裸输入框。
  2) 当天可点"今天特殊"覆盖一个值。
  3) 系统建议：连续 3 天完成率 < 60% 时，提示"要不要把周二从 3h 调到 2h"，
     用户点确认才写库。禁止自动改参数。

【时间的三种来源，必须一眼可分，且行为不同】
1. 固定占用 is_fixed=true → 整行深色实心块，不可拖
2. 系统推荐 slot_source='ai' → 虚线边框 + "系统推荐"标签 + 必须给一句 ≤20 字理由
3. 你定的 slot_source='user', is_locked=true → 实线边框 + "已锁定"，不显示理由
规则：只有 ai 态会在重排时变动；用户一拖立刻变 user + 锁定；
点锁定可解除退回 ai；重排时跳过 is_fixed 与 is_locked，剩余容量
= 当天可用 − 已锁定占用 − 固定占用。

【队列视图（唯一主入口）】只允许四种东西，不许加第五种：
  · 固定行：深色 + 左侧竖条 + 名称/时间
  · 空档线：一行 11px 灰字，如"15:40 之后 · 可用 1.5 小时"
  · 任务卡：白底描边，标题 + 估时 + 推算时段 + 理由（仅推荐卡有）
  · 尽力线：横线 +"今天到此为止"，线下褪色标"明天"
禁止：时间刻度栏、日历网格、绝对定位时间轴、横向滚动、分屏并行。

【不要做"提交前确认"】
  输入后直接进队列：不弹确认窗、不弹"已排好"提示、不要求点"确定"。
  解析结果直接呈现在卡片上（时间/时长可点改）——这是确认理解，不是确认顺序。
  三态：读懂了直接显示；不确定显示并带虚线下划线可点改；没读懂显示"未定时间·补一个"。
  原则是「沉默即同意」——不改就是同意，改才动手，永远不要"请你确认"。
  一次粘 8 条以上时，给一个轻量清单："已拆成 7 条，其中 1 条没看懂时间"，逐条可改。
  没写估时的任务默认 30 分钟。
  拖拽即时生效，不弹"已保存"，但必须支持一步撤销。

【防遗漏，三处都要有】
  ① 顶部："今天 8 件 · 已排 3 件"
  ② 队列底部："还有 5 件没排上 · 展开"
  ③ "全部清单"入口（纯列表，按到期/创建排，不进任何时间结构）

【/api/bucket】AI 只做分档，不做排序，不输出时钟时间。
  分档输入必须带 age（记了多久，天）和 slack（今日剩余容量占比）。
  没提时间的默认 today，不是 later（进 later 会蒸发）；
  age > 3 天仍未完成 → 至少升到 today。
  输入：now, available_min(当天), fixed_events[], new_task（或待重分的任务）,
        recent_corrections[], prefs[]
  输出：{id, bucket, reason}，bucket ∈ now|today|week|later，reason ≤ 20 字。
  reason 只能引用输入里已有的字段（标题、截止、估时、顺延次数），
  不许编造进度/难度/谁在等这件事；更稳的做法是 reason 由代码拼装，
  AI 只给 bucket。理由里每个字都必须能核对。
  一次只处理少量任务（新增的、或被要求重分的），不要每次全量。
  允许"档位靠前但物理上装到后面"：卡片标注"排第 N，装到 16:00"，
  不要改档位去对齐时间。
  返回的每条必须带 slot_source='ai'，用户拖过的不许覆盖。

【代码定序，不用 AI】
  顺序 = 按档位分组(now>today>week>later) → 组内按 (due_at 升序, est_min 升序)，
        没有截止时间的排在本组末尾。
  起点 = max(现在, work_start)。
  空档分三类，不许一刀切丢弃：
    整块 ≥30 分钟 → 可放任意任务
    碎片 10–30 分钟 → 只放 est_min ≤ 该时长的任务
    <10 分钟 → 丢弃
  装填跑两轮：
    第一轮 按序装整块，放不下就跳到下一个整块
    第二轮 把剩下的短任务回填碎片（10 分钟的取快递必须能塞进去）
  撞容量画"今天到此为止"。没有任何权重公式，没有任何系数。

【排序优先级三层】
  1. pinned=true → 绝对不动
  2. manual_priority=true → 档位由用户锁死，AI 不得改
  3. 其余 → AI 分档
  importance 与 urgency_manual 是硬输入，模型不能覆盖用户标过的值。

【排完序后代码跑四道闸，不许改 AI 给的顺序】
  闸1 合法性：id 必须来自输入集，编造的丢弃，漏掉的补队尾
  闸2 容量：累加 est_min，撞到当天可用时长画"今天到此为止"
  闸3 硬约束：固定行按时间插位；due_at 已过今天的强制置顶标红
  闸4 稳定化：与上日 rank 比，位移>5 且当天无新信息则回退原位

【降级三层，不写任何算法重排逻辑】
  1) 超时 8s 重试 1 次
  2) 失败读上次 ordered_json 快照直接用
  3) 打星/拖拽永远可用，本地立即生效，不经过 AI
  出现 2) 时顶部灰字提示"用的是上次顺序"，绝不显示空列表。

【数据安全】一键导出/导入 JSON（走系统分享面板）。
  每周第一次打开提醒导出。AI key 只存 localStorage 由用户输入，绝不硬编码。

【不做】课表导入、周视图网格、14 天负载条、四象限、云同步、账号、多端、
团队协作、甘特图、ics、自研语音、主题皮肤、任何动画。

【交付】npm run dev 能跑；README 写清：AI key 怎么填、
day_capacity 怎么调、prefs 怎么写、Capacitor 打包命令。
```

## 三、验收标准（9 条，前 5 条不过就别往下走）

- [ ] 粘一段 5 件事的乱文本（含"周四前""下周三下午"），一次拆成 5 条，时间不乱
- [ ] 写一句完全没时间的（"研究下 Notion 模板"），进清单而不是报错
- [ ] **设周二为 120 分钟，塞 300 分钟任务，只有约 120 分钟的进今天，其余标"明天"**
- [ ] **点"今天特殊"改成 60 分钟，队列立刻重排收敛**
- [ ] **系统推荐卡是虚线 + 有标签 + 有理由；拖后变实线 + "已锁定" + 理由消失**
- [ ] 拖过的卡再点"重排"，位置不动
- [ ] **输入 3 条任务，全程没有任何弹窗或"确认"按钮，任务直接出现在队列里**
- [ ] **拖乱顺序后能一步撤销回原样**
- [ ] 顶部显示"今天 N 件 · 已排 M 件"，底部显示"还有 K 件没排上"
- [ ] 断网调 /api/bucket，显示上次档位与顺序 + 灰字提示，不白屏
- [ ] 导出 JSON 后清空数据再导入，任务都回来了

第 3、4 条验的是"可用时间真的按天算"，不是拿一个全局数字糊弄。
第 5 条验"'谁定的'一眼可见"——做不到这条，用户会同时不信任 AI 和不敢改它。

## 四、两周后看什么

| 指标 | 及格线 | 不达标说明什么 |
|---|---|---|
| 解锁到提交一条任务 | **≤ 10 秒** | 捕获有摩擦，先修这个 |
| 连续使用天数 | ≥ 10 天 | 顺手度不够 |
| 计划完成率 | 60%–85% | **>90% 说明容量设太低，浪费了产能；<50% 说明设太高** |
| 手动改序 / 天 | 3–8 次 | 太少=没在管；太多=排得差 |
| 有没有"漏掉一件事"的时刻 | 0–1 次/周 | 超过就要强化防遗漏三处 |

第三行是个双向指标，容易被误读：完成率不是越高越好。**长期 100% 完成，说明你把自己排得太松了。**
