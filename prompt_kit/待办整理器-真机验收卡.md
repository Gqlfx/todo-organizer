# 待办整理器 · 真机验收卡

> 前提：从 `https://cdn.jsdelivr.net/gh/<用户名>/<仓库名>@apk/app-debug.apk` 下载并安装，
> 系统设置里允许「安装未知来源」。
> 四条按顺序做，任何一条不过就先停在那一条，不要往后跑。

## 1. 填 key → 掩码显示

**怎么做**：设置 → AI Key → 粘贴 `sk-...` → 点空白处（失焦）

| 结果 | 判读 |
|---|---|
| ✅ 输入框是圆点，下面显示 `已保存 ••••后四位` | 通过 |
| ❌ 显示「未填」 | 没写进库：Dexie 事务失败或被 WebView 拦了，看 logcat |
| ❌ 明文可见 | 输入框 `type` 不是 password，代码被改坏了 |

## 2. 没有「没填 AI Key」提示

**怎么做**：填完 key 回队列页，看顶部

| 结果 | 判读 |
|---|---|
| ✅ 顶部没有橙色那行 | 通过（说明读到 `ai_key` 非空） |
| ❌ 还在 | 库里还是空的——先回设置确认第 1 条真过了；再不行是 `isNative()` 判断异常 |

> 这行的作用就是替你在第 3 条失败前先报信，别跳过它。

## 3. 「明天下午三点开会」→ 固定行 15:00–16:00

**怎么做**：队列页输入框粘贴这句，回车，等 3–5 秒

| 结果 | 判读 |
|---|---|
| ✅ 出现深色固定行，右侧 `15:00–16:00` | 通过：key + 直连 + CapacitorHttp 三件一起成立 |
| ❌ 卡片停在「未定时间」 | 请求没成功。看 logcat：`HTTP 401` = key 错；`请求没发出去` = 网络或 CapacitorHttp 没生效 |
| ❌ 卡片在但没变成固定行 | 解析成功了但 `is_fixed` 判错，是 prompt 的问题，不是原生问题 |
| ❌ 卡片直接消失 | 严重：固定事件被当成不占今天的，去查 `computeQueue` 的过滤 |

**查日志**：

```bash
adb logcat -s "Capacitor/Console:V" "Capacitor:V" | grep -iE "llm|error|http"
```

## 4. 导出 → 系统分享面板

**怎么做**：设置 → 备份 → 导出 JSON

| 结果 | 判读 |
|---|---|
| ✅ 弹系统分享面板，能看到 `todo-YYYY-MM-DD.json` | 通过：Filesystem 写成 + FileProvider 转 URI 都对 |
| ❌ 完全没反应 | `Filesystem.writeFile` 失败；查是不是权限被拒（Cache 目录不该需要权限） |
| ❌ 面板闪一下就消失 | `Share.share` 抛异常被吞了；改代码把 catch 里的日志打出来再看 |

分享面板里选「保存到文件」才会真正落盘；选微信/邮件就是发出去。取消不算失败。

## 附：四条都过之后

一次真机验证覆盖了三层：

1. **Key 链路**：Dexie 写入 → 读取 → 拼进 Authorization
2. **网络链路**：CapacitorHttp 接管 fetch → 越过 CORS → DeepSeek 返回
3. **原生能力**：Filesystem 写缓存 → FileProvider → Share 面板

这三层任何一层断了，前面两条仍会通过——所以四条必须按顺序全做完，不能只看第 1 条就收工。
