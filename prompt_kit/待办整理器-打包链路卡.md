# 待办整理器 · Android 打包卡（CI 方案）

> 2026-11-17 定：**本机不装 JDK / Android SDK**，出包交给 GitHub Actions。
> 本机只需要保证两件事：`npm run build` 和 `npx cap sync`。

## 一、分工

| 谁 | 做什么 |
|---|---|
| 本机（WorkBuddy 沙箱） | 写代码、`npm run build`、`npx cap sync`，不编译 APK |
| GitHub Actions | `gradlew assembleDebug` 出包，推到 `apk` 分支 |
| 手机 | 从 jsDelivr 下载 `app-debug.apk` 安装 |

## 二、仓库要求（配 workflow 前先确认）

1. **`android/` 必须提交**。根 `.gitignore` 里原来有 `android` / `ios` 两行，已删掉；
   构建产物由 `android/.gitignore` 自己挡（`.gradle/`、`build/`、`assets/public`、生成的 config）。
   如果不放行，CI 里根本没有原生工程，`cap sync` 会直接报「android platform not found」。
2. `android/app/build.gradle` 的 `namespace` / `applicationId` 都是 `com.syq.todo`；
   `values/strings.xml` 的 `app_name` / `title_activity_main` 是「待办」。
   `npx cap sync` 不会覆盖这几个文件。
3. `android/app/src/main/java/` 下只有 `com/syq/todo/MainActivity.java` 一个文件。
   模板残留的 `com/getcapacitor/` 已删除——两个同名 MainActivity 会让 `assembleDebug`
   报 duplicate class。

## 三、CI 四步

```bash
npm ci
npm run build
npx cap sync
cd android && ./gradlew assembleDebug
```

产物：`android/app/build/outputs/apk/debug/app-debug.apk`

GitHub Actions 上还需要（workflow 里配）：
- `actions/setup-java@v4`，`java-version: 17`、`distribution: temurin`
- `android-actions/setup-android@v3`（ubuntu-latest 也预装了 SDK，二选一）
- `chmod +x android/gradlew`（从 Windows 提交会丢可执行位，这是最常见的 CI 报错）

## 四、本机 `npx cap sync` 的坑（只有 WorkBuddy 沙箱有）

`cap sync` 每次都会先删掉再重建这两个目录：

```
android/app/src/main/assets/public
android/capacitor-cordova-android-plugins
```

沙箱的 safe-delete 拒绝删除**非空目录**（报 `trash operation ... Some operations were aborted`），
但删单个文件和空目录是允许的。所以第一次之后要先把它们清成空壳：

```bash
find android/app/src/main/assets/public android/capacitor-cordova-android-plugins \
  -type f -delete 2>/dev/null
find android/app/src/main/assets/public android/capacitor-cordova-android-plugins \
  -depth -type d -exec rmdir {} + 2>/dev/null
npx cap sync
```

CI 上是普通文件系统，不需要这一步。

## 五、产物通道：jsDelivr（不走 artifact）

workflow 里 `assembleDebug` 之后：

1. 把 `android/app/build/outputs/apk/debug/app-debug.apk` 拷成 `apk/app-debug.apk`
2. 用 `peaceiris/actions-gh-pages` 或原生 git 推到 `apk` 分支
3. 同时保留 `upload-artifact` 作为备份（本地能开梯子时用）

手机下载地址：

```
https://cdn.jsdelivr.net/gh/<用户名>/<仓库名>@apk/app-debug.apk
```

注意：
- debug APK 必须 **< 20 MB**，超了 jsDelivr 不服务
- 推送后等 **3–5 分钟**再点链接，首次同步有延迟
- 手机装之前要在系统设置里允许「安装未知来源」

## 六、打出来的包会缺什么（已知，下一步补）

`/api/llm` 是 **Vite dev server 的代理**，APK 里没有这个代理，所以装到手机上：

- 建卡、队列、设置能用
- **解析和分档会直接失败**，任务全部停在「未定时间」/ `today`
- 导出用 `Blob + <a download>`，在 WebView 里能否落地未验

所以顺序是：三处原生适配（AI Key 输入 → `/api/llm` 双分支 → 导出走 Filesystem）**做完再打包**。
