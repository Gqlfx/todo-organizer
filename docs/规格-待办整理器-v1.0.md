# 待办整理器 · 规格 v1.0（冻结）

> 2026-11-16 冻结 ｜ 本文替代 v0.1–v0.4，开工以此为准
> **修订 2（13:14）**：Task 新增 `plan_date`。此前没有这个字段，"顺延到明天""线下标明天"无处落地——
> 队列只按 bucket 过滤，明天这些任务仍然是"今天"，不会自己滚过去。
> 一句话：**随口输入 → 自动分档 → 一条今天能做完的队列。**

---

## 一、不可动摇的五条

任何后续改动都不能违背这五条，否则产品性质就变了。

1. **输入即入队**——没有确认弹窗，没有"已排好"提示
2. **AI 只分档，代码定序**——不给 AI 排序权，不设权重公式
3. **手动优先**——拖了就锁定，重排永远不动它
4. **容量按天算**——七天七个值，不是一个数字
5. **单机、本地、可导出**——不做云、不留同步字段

---

## 二、数据模型（最终）

```
Task
  id, title, raw_input, status(todo|done|deferred|dropped)
  -- 固定占用
  is_fixed, start_at, end_at, repeat(none|weekly)
  -- 软任务
  est_min, due_at
  -- 判定
  bucket(now|today|week|later), bucket_reason, manual_priority
  importance(1-5), urgency_manual
  -- 排布
  plan_date(YYYY-MM-DD|null), ---- "我打算哪天做"。null 视为今天。
  queue_rank, slot_source(ai|user), is_locked, pinned, defer_count
  -- 溯源
  parse_confidence, created_at, done_at

Settings
  day_capacity { 1..7: 分钟 }
  capacity_override { "YYYY-MM-DD": 分钟 }
  work_start("08:00"), work_end("23:00")
  buffer_min(10), min_gap_min(15)
  prefs_json, ai_key
```

**不存**：`gap`（每次运行时算）、`user_id`、`updated_at`、`synced_at`。

## 三、四个流程

### 3.1 捕获 → 解析

```
输入（多行 = 多条）→ /api/parse → Task 草稿 → 直接入队
```

- 解析失败不报错：存原文，`bucket = later`，卡片显示"未定时间"
- 一次 ≥8 条时，才给一个轻量清单："已拆成 7 条，其中 1 条没看懂时间"

### 3.2 分档

```
输入：now, 任务本身, age(记了多久), slack(今日剩余容量占比), 最近 20 条改档记录
输出：{ id, bucket, reason }
reason 只能引用已有字段（截止/估时/顺延次数），不许编造
```

**时态词表**（写进 prompt，靠它把模糊表达映射成档位）：

| 说法 | 档位 |
|---|---|
| 一会 / 马上 / 顺手 / 现在 | `now` |
| 今天 / 今晚 / 待会 | `today` |
| 这周 / 这几天 / 下周初 | `week` |
| 有空再说 / 以后 / 不急 | `later` |
| **没提时间** | **`today`**（不是 later） |

两条硬规则：

1. **没提时间 ≠ 不急。** 只是你没说。进 `later` 它会蒸发，那正好是你抱怨的"想不起来"。
   所以默认进 `today`，组内排在有截止的任务之后——既不蒸发，也不抢占。
2. **`age > 3 天`且仍未完成 → 至少升到 `today`。** 一条在 later 躺了一周的任务，
   已经在用行动告诉你它重要。

不传全部任务，不要求全序。新任务只问一句"这条放哪档"。

### 3.3 定序与装填（全代码）

```
顺序 = 按档位分组(now > today > week > later)
     → 组内按 (due_at 升序, est_min 升序)，无截止的排本组末尾
     → 起点 = max(现在, work_start)
     → 两轮装填：
         第一轮  按序装整块（≥30 分钟），放不下跳到下一个整块
         第二轮  剩余短任务回填碎片（10–30 分钟，只放 est_min ≤ 该时长）
     → 撞到当天容量画"今天到此为止"
later 档不占今天容量
```

**空档不能一刀切丢弃。** 如果固定丢掉 <15 分钟的空档，"取快递（10 分钟）"永远排不进去——这是个硬 bug。规则改为：<10 分钟才丢，10–30 分钟保留为"碎片"，专门喂短任务。

**紧张度不需要新算法。** `slack`（今日剩余容量占比）只做两件事：喂给分档做参考、显示在顶部让你自己判断。真正的弹性来自两轮装填——任务会自动滑到下一个放得下的地方，而不是硬塞在这一刻之后。

**允许顺序与时间错位**：档位靠前但当天装不下时，卡片标注"排第 N，装到 HH:MM"，不改档位去对齐。

### 3.4 完成与顺延

- 完成：点卡片左侧圆圈，`status = done`，从队列消失（数据保留）
- 顺延：找**下一个装得下的日子**（最多搜 7 天），不是机械 +1 天
- 每次顺延 `defer_count + 1`，卡片理由里会显示"已顺延 N 次"

## 五、解析确认：沉默即同意

这是本轮定稿的机制。**没有"确认"这个动作**，解析结果直接长在卡片上：

| 状态 | 呈现 | 用户行为 |
|---|---|---|
| 读懂了 | 直接显示"明天 15:00" | 什么都不做 = 同意 |
| 不确定 | 显示但带虚线下划线，"明天 15:00" | 点一下可改 |
| 没读懂 | 显示"未定时间 · 补一个" | 想补就补，不补进 later |

**逻辑是反的**：不是"请你确认"，是"不同意才动手"。

理由：任何形式的"确认"都要求一次点击，而点击是有成本的。做成"沉默即同意"，成本为零，同时又保留了可改入口。

**撤销比确认重要**：拖拽即时生效，不弹"已保存"，但必须能一步撤销（连续撤 3 步）。

## 六、五个默认值（我替你做的主，不同意就说）

| 项 | 默认值 | 理由 |
|---|---|---|
| 没写估时的任务 | 30 分钟 | 一个番茄，宁可低估 |
| 推算时段起点 | `max(现在, work_start)` | 昨天记的今天仍从 work_start 起算 |
| 无明确时间的任务 | 进 `today` 档，排在有截止的之后 | 进 later 会蒸发 |
| 顺延 | 找下一个装得下的日子（≤7 天） | 机械 +1 天会撞上满课日 |
| 完成后的任务 | 保留数据，列表隐藏 | 不做历史页，但数据不删 |
| 产品名 | 暂叫"待办" | 不值得在这上面花时间 |
