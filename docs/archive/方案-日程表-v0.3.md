## 一、三个视图，职责不同（回答"并行还是切换"）

**不是并行，是分层。**

| 视图 | 回答什么问题 | 打开频率 | 可编辑什么 |
|---|---|---|---|
| **队列（唯一主入口）** | 现在做什么 | 每次打开 | 拖拽、打星、完成 |
| 课表 | 这周什么时候有课 | 每周几次 | 点开改（核对导入） |
| 四象限 | 我是不是只顾救火 | 每周一次 | 拖拽改分类 |

**为什么不做并行（分屏）**：

1. 手机屏幕宽度放不下两栏，硬塞会两边都难看
2. 并行意味着每次打开都要先做一次"看哪个"的选择，**选择本身就是成本**
3. 更关键——**并行的真实需求已经被吸收了**：你既想知道"现在做什么"，又想知道"几点上课"，这两件事队列本身就能同时回答（见第二节，课程会作为不可拖的行出现在队列里）

三个视图是三种动作，不是一个东西的三张皮：

- 队列 = **执行**
- 课表 = **查阅**
- 四象限 = **审视**

## 二、课程占时间，是计算问题，不是展示问题

这是上一版最容易误读的地方。课程对界面的影响只有**两个出口**，除此之外不改变任何东西：

**出口 1：队列里多出几行"不可拖的深色行"**

**出口 2：任务卡的推算时刻被压缩**（白天空档只有 80 分钟，90 分钟的任务自动落到晚上）

界面永远是一条纵向列表。**没有时间刻度栏、没有网格、没有绝对定位。** 真正的日历视图只存在于"课表"那个 Tab 里。

### 2.1 队列里只有四种东西

```
▎08:00–09:40  高数              教三 201      ← 课程行（深色、不可拖）
▎10:00–11:40  英语              外语楼 305    ← 课程行

  · · · 11:40–14:00 可用 80 分钟 · · ·          ← 空档线（极轻，11px 灰字）

  买猫粮                    10 分钟            ← 任务卡（可拖）
  12:05–12:15 · 顺路

  回邮件                    25 分钟
  12:25–12:50 · 三封都是急的

▎14:00–15:40  电路实验（单周）  实验楼 B       ← 课程行

  · · · 15:40 之后 可用 6 小时 · · ·

  方案给老板                90 分钟
  16:00–17:30 · 白天装不下，只能排这儿
```

规则：

- **课程行**：整行深色底、左侧竖条、文字 500、右侧时间；不可拖，拖了会弹"课程要去课表改"
- **空档线**：一行 11px 灰字，不占视觉重量，只负责回答"这段够不够"
- **任务卡**：白底描边，标题 + 估时 + 推算时段 + 一句理由
- **尽力线**：横线 + "今天到此为止"，线下褪色归明天

### 2.2 装填逻辑（不变）

```
AI 定序 → 代码逐空档 first-fit 装填 → 装不下下沉到下一个空档 → 今天全满归明天
```

允许 **rank 与时间错位**：AI 排第 1 的任务，若白天空档都不足 90 分钟，会落到 16:00。卡片上标注"排第 1，白天装不下"，不要偷偷改顺序去对齐。

## 三、课表：学期模板

### 3.1 数据模型

```
Course（学期模板）
  id, name, location, teacher, color
  weekday      1–7
  start_time, end_time
  weeks        "1-16" 或 "1-8,10-16"
  parity       all | odd | even

Task（一次性的事）
  id, title, raw_input, status
  is_fixed, start_at, end_at, is_all_day, prep_min   -- 一次性固定事件：面试、航班
  est_min, due_at
  importance, urgency_manual, manual_priority, quadrant
  queue_rank, rank_reason, pinned
  created_at, done_at

Settings
  semester_start, work_start, work_end, buffer_min, min_gap_min
  prefs_json, ai_key
```

课程是模板，日程是实例。两者生命周期不同：课表跟学期走，待办跟日子走。

### 3.2 一天怎么算出来

```
expandDay(date):
  week    = 相对 semester_start 的第几周
  courses = Course 中 weekday 匹配 && weeks 命中 && parity 命中
  events  = courses 实例化 + Task 中 is_fixed 落在当天的
  gaps    = 用 events 把 [work_start, work_end] 切成空档
  空档    = [上一事件结束 + buffer, 下一事件开始 − prep_min]，< 15 分钟丢弃
```

代入一个真实的周二（第 7 周，单周）：

```
08:00–09:40  高数
10:00–11:40  英语
14:00–15:40  电路实验（单周才有）

空档 09:40–10:00   20 分钟 → 丢弃
空档 11:40–14:00  140 分钟，扣午饭 60 → 80 分钟
空档 15:40–22:00  380 分钟，但晚上效率低
```

**真实约束不是"今天可用 8 小时"，是"一段 80 分钟 + 一个晚上"。** 90 分钟的任务白天根本放不进去。

### 3.3 课表视图（Tab 2）

只读周网格（周一至周日 × 时段），点开单条可编辑删除。

**这一页必须有**：导入必然出错，没有核对入口等于没导入。它同时也回答"周三下午有没有课"。

## 四、课表导入：AI 做一次性结构化

教务系统导出格式不可控（Excel 网格 / ics / 网页表格），写解析器是给自己挖坑。

**做法：粘贴 + AI 结构化。**

1. 从教务系统复制课表网格，粘进 textarea
2. 发给 AI 要 `Course[]` JSON（含 weekday / 时间 / 周次 / 单双周 / 地点）
3. 预览 + 人工修正 → 写入
4. 一定要走一次课表视图核对

格式变了不用改代码 —— 这是"依附 AI"这个前提最划算的一次应用。ics 导入放 V0.1.1。

## 五、手动优先级是一等公民

```
1. pinned          手动钉住 → 绝对不动
2. manual_priority 手动设过重要性/紧急性 → AI 必须尊重，只能在其内部调整
3. AI 判断         你没表态的部分 → AI 自由排
```

`importance`(1–5) 与 `urgency_manual` 是**硬输入**，模型不得覆盖你点过的星。

UI：每张卡右侧两个小控件——重要性打星（●●●○○）、紧急性可覆盖（默认按 deadline 算）。

**AI 挂了，产品功能不减，只是少了"一键排"。** 而且你随时能接管，所以不怕它排错。

## 六、手机端与打包

| 路线 | 成本 | 问题 |
|---|---|---|
| 重装 Android Studio 写原生 | 2–4 周 | 价值在 AI 编排不在性能 |
| 纯 PWA 部署静态托管 | 半天 | 国内静态域名访问不稳 |
| **Capacitor 套壳打 APK** | **1–2 小时** | 无（iOS 用不了，你是 Android） |

**不需要 Android Studio**，只依赖 JDK 17 + Android SDK 命令行工具：

```
npm run build && npx cap add android && npx cap sync
cd android && ./gradlew assembleDebug
```

或用 GitHub Actions 云构建，APK 当产物下载。

**顺序：90% 时间做纯 Web，最后花 1 小时套壳。**

手机端四个设计差异：语音输入交给系统输入法（不自己做）；纯前端打开即用（不做启动动画）；提醒用 Capacitor Local Notifications（V0.1.1）；数据靠导出 JSON 保底。

## 七、数据与同步：不做云，也不留钩子

**结论：单设备、纯本地、无同步。**

- 不做云端账号，不做"电脑开机时同步"
- **连 `user_id`、`updated_at`、`synced_at` 这类字段都不留** —— 留了就会诱导以后去填，复杂度是从一个字段长出来的
- 一台设备一个数据库，换手机靠导出/导入 JSON
- 电脑上想用？导出导入，或者干脆不用

**唯一保险：导出 JSON。** 走系统分享面板发微信/存网盘，每周第一次打开时提醒一次。这条不能省——手机丢了数据就没了。

## 十、风险

1. **课表导入错 → 全天空档算错**。对策：课表视图必核对，导入后强制预览。
2. **周次算错**（单双周、开学日期）。界面上显示"第 7 周"，让你一眼看出不对。
3. **手机端不顺手就弃用**。指标：解锁到提交一条任务 ≤ 15 秒。
4. **排序人格漂移** → 四道闸第 4 道（位移 > 5 且无新信息则回退）。
5. **数据只在一台手机上** → 导出 JSON 是唯一保险。
6. **工期膨胀** → 任何新想法进 V0.1.1，不进首版。
