# 日程表 · 产品方案 v0.2（修订，已归档）

> ⚠️ **已被 `方案-日程表-v0.3.md` 取代**：主设备改为手机、架构改 Vite 纯前端、新增课表模板、手动优先级升为一等公民。此处留作决策记录，勿按本文档开发。

**一条设计原则，贯穿全文：**

> AI 给**序数**，代码翻译成**基数**。
> 凡是"判断"交给模型，凡是"算术"交给代码，凡是"取舍"交给你。

## 变更记录

| # | 改了什么 | 为什么 |
|---|---|---|
| 1 | 主视图：时间轴 → **队列** | 队列只要 AI 做相对排序（序数），时间轴要它做时间算术（基数） |
| 2 | 排序：确定性权重公式 → **AI 统筹** | 权重系数是拍脑袋定的，换个人就失效 |
| 3 | 容量取舍：弹窗 → **今日尽力线** | 队列天然能表达"到这儿为止" |
| 4 | 存储：IndexedDB → **本地 SQLite** | IndexedDB 各设备各存一份，多端等于没做 |
| 5 | 形态：**单机定案** | 电脑用完就关，多端推迟；手机端用 ics 导出补（见 8.3） |
| 6 | 固定事件：从"锚点"升级为**骨架** | 会议、上课、竞赛不是"待办"，它们定义了这一天的形状 |
| 7 | 视图：纯队列 → **时间流（骨架 + 空档 + 队列）** | 只有队列会失去时间感，只有时间轴会退化成手工排程 |
| 8 | 删掉"算法兜底"的设想 | 用规则重排需要清晰语料，做不到。改为三层退化（见第六节） |

## 一、一句话定义

不是日历，是**这一天被切成了几块、每块里按什么顺序做**。

四象限是另一扇门，用来看你为什么这么排；不是主界面。

---

## 二、四个已定决定

1. **双轨制**：固定事件占时间，软任务进队列；两者共用一份数据，规则不同
2. **排序由 AI 统筹**（既定前提，不再讨论替代方案）
3. **容量即取舍**：填到今日容量撞线，画"今天到此为止"，线下归明天
4. **单机、本地、零月费**：电脑当真身，手机靠导出补

---

## 三、双轨模型（本轮最核心）

### 3.1 两类东西，两套规则

| | 固定事件 | 软任务 |
|---|---|---|
| 例子 | 开会、上课、竞赛、航班、约人、面试 | 写方案、回邮件、买猫粮、改 PPT |
| 时间 | start + end 确定 | 只有估时 + 截止 |
| 能否移动 | 不能（外部世界定的） | 能 |
| 能否并行 | 否，独占整段 | 可在碎片里做 |
| 占不占容量 | **占满，且不可侵占** | 按估时占 |
| 位置谁定 | 你（录入时给） | AI 定序、代码定位 |
| 标记 | `is_fixed = true` | `is_fixed = false` |

**这是两条不同的时间语义，不能挤进一套规则。** 把它们混在一起，就是大部分日程软件用不起来的根源：开会和"写周报"在列表里长得一样，于是你既不知道几点要出门，也不知道现在该做什么。

### 3.2 一天的形状由固定事件切出来

```
gap（空档）= [上一个硬事件的结束 + 缓冲, 下一个硬事件的开始 − 准备时间]
```

- **缓冲**默认 10 分钟，防止连轴转
- **准备时间**：通勤/出门类事件单独设（14:30 要出发，那 14:30 之后就不算空档）
- 空档小于 15 分钟直接丢弃，不值得排

一天 = 若干硬块 + 若干空档，交替排列。硬块是**不可逾越的分割线**，任务不能跨过去。

### 3.3 AI 定序，代码定位（对"AI 统筹"的精确化）

```
AI 输出：一个全局有序列表 + 每条的 est_min + 一句理由
代码做：按这个顺序，逐条 first-fit 装进空档，算出"预计 10:15–10:40"
代码不改顺序，只把序数翻译成时钟时间
唯一例外：deadline 已过 / 固定事件冲突，可强制置顶并标注原因
```

**关键细节：允许"顺序靠前，但时间靠后"。** 比如 AI 把 90 分钟的"方案"排第 1，但第一个空档只有 40 分钟，first-fit 会把它装到 13:00 那段。这时界面必须按时间轴显示位置，同时保留卡片上的 rank 序号 —— 让用户看到"AI 认为它第一，但物理上只能排到 13:00"。不解释这一点，用户会以为排序坏了。

### 3.4 容量必须按空档算，不能按天算

v0.2 之前写的"今日容量 330 分钟"是粗算，会出这种错：**总容量够，但没有一个连续 90 分钟的空档。**

正确做法：
```
今日容量 = Σ 每个 gap 的分钟数
填充时逐个 gap 装，任务不跨 gap（跨了就拆成两段）
这个 gap 满了 → 下一个；今天全满 → 归明天
预计收工 = 最后一条被装进去的任务的结束时间
```

### 3.5 录入：一个框，自动判类型

同一个输入框，用户不区分"待办"和"日程"：

| 输入 | 解析结果 |
|---|---|
| 周三下午三点开组会，大概一小时 | `is_fixed=true`, `start_at=周三15:00`, `est_min=60` |
| 周四前把方案给老板 | `is_fixed=false`, `due_at=周四18:00`, `est_min=90` |
| 周六上午九点竞赛，一整天 | `is_fixed=true`, `is_all_day=true` |

判定规则（给 AI 的提示，不是给代码的）：
- 有**明确开始时刻** + **人/地点/场所** + 会**独占一段时间** → 固定事件
- 只有截止时间 → 软任务
- 拿不准 → 默认软任务，卡片上给一个"改成固定事件"的小开关

这条歧义不可能消除（"周三前交材料"到底算不算固定？），所以**必须留一键切换**，而不是追求解析准确率。

### 3.6 重复与全天

- **重复**：只做 `none | daily | weekly | weekdays` + `repeat_until`。不做 RRULE 全集（BYDAY/BYSETPOS/例外/时区），那是日历软件的复杂度黑洞。每天上课、每周例会，这个粒度够覆盖 80%。
- **全天事件**（竞赛、出差、请假）：`is_all_day=true` → 当天所有空档清零。人在外面，就不该再排 40 分钟的活。

## 四、AI 统筹的边界：四道闸

AI 排完序，代码再跑一遍校验，**且不改它给的顺序**：

1. **合法性**：输出的 id 必须来自输入集。编造的丢弃，漏掉的按 `due_at` 补队尾
2. **容量**：逐 gap 装填，装不下的下沉。代码只画线，不判断谁该留
3. **硬约束**：固定事件按时间插位；`due_at` 已过今天的强制置顶标红
4. **稳定化**：与上日 rank 比，位移 > 5 且当天无新信息（新任务/完成/拖拽）→ 回退原位

第 4 道是最容易翻车的地方。没有它，你会每天看到一张陌生清单，三周后放弃，然后怪"AI 排得不准"。**用户不信任排程，原因通常不是排得差，是每天都变。**

**触发时机**（别每刷新一次就重排）：新任务入池 / 任务完成或删除 / 手动拖拽 / 跨天首次打开 / 点"重排"。其余用上次结果，`cache_key = hash(任务池+日期)`。

## 五、时间流视图

```
11月15日 周日          可用 3.5 小时 · 预计 17:40 收工
──────────────────────────────────────────────
09:00  空档 150 分钟
       ▸ 方案给老板   90 分钟  09:10–10:40  周四到期，还差两轮
         回三封邮件    25 分钟  10:50–11:15
11:30  ███ 通勤 + 午饭        不可用
13:00  空档 120 分钟
         买猫粮        10 分钟  13:05–13:15
         写周报        40 分钟  13:25–14:05
       ─ ─ ─ 今天到此为止 ─ ─ ─
         整理桌面      15 分钟  → 明天
15:00  ███ 组会        15:00–16:00 · 固定 · 不可拖
16:00  空档 60 分钟
...
```

视觉规则（三条就够）：

- **硬块满宽、深色、不可拖**，一眼能数出今天有几个会
- **空档是淡色区域**，右上角标总分钟数，让你知道"这块能塞多少"
- **软任务是普通卡片**，可拖，带估时 + 推算时段 + 一句理由

**为什么不用纯时间轴**：时间轴逼你为每件事指定开始时间，那是手工排程，AI 就没事干了。
**为什么不用纯队列**：队列看不见"11:30 要出门"，会让人产生"今天还早"的错觉。

时间流 = 骨架给你约束，队列给你顺序。两者缺一，这个产品就不成立。

## 六、降级：不做算法兜底，做三层退化

**明确记下这个结论，别再走回头路：用本地算法替代 AI 排序不可行。** 要把"这件事比那件事重要"写清楚，需要的是清晰语料和稳定规则，而个人日程恰恰两者都没有。做了也是错的，错得还很自信。

所以兜底不是"替代 AI 思考"，而是"AI 不在时保持现状 + 保留你手动改的能力"：

| 层 | 做法 | 成本 |
|---|---|---|
| 1 | 超时 8 秒、重试 1 次 | 3 行 |
| 2 | **快照回退**：`RankLog` 里存着上次的 `ordered_json`，直接用 | 0（表已经存在） |
| 3 | **手动拖拽永远可用**：本地即时生效，写 `queue_rank`，不经过 AI | 0（本来就是主交互） |

三层都不需要语料。第 3 层尤其重要 —— 它让"AI 挂了"从事故降级为不便。

## 七、数据模型

```
Task
  id, title, raw_input, status(todo/doing/done/deferred/dropped)
  -- 固定事件
  is_fixed, start_at, end_at, is_all_day, prep_min, location
  repeat(none|daily|weekly|weekdays), repeat_until, series_id
  -- 软任务
  est_min, due_at
  -- 判定
  suggested_importance, importance, urgency_manual, quadrant(派生)
  -- 队列
  queue_rank, rank_reason, pinned, defer_count
  created_at, done_at

RankLog                       -- 排序快照，降级层 2 的燃料
  id, created_at, trigger, model, input_hash,
  ordered_json, user_edits_json, latency_ms, tokens

Settings
  work_start, work_end, buffer_min, min_gap_min,
  prefs_json, model_config
```

`gap` 不存库，每次运行时由 `fixed_events + Settings` 算出来。存了就会不一致。

## 八、技术方案

### 8.1 栈

| 层 | 选型 |
|---|---|
| 框架 | Next.js 15 + TS + Tailwind + shadcn/ui（前后端一个进程） |
| 存储 | better-sqlite3 + drizzle-orm，`data/app.db` 单文件 |
| 拖拽 | dnd-kit（时间流和四象限共用） |
| AI | 服务端 `/api/parse`、`/api/rank`，模型 `deepseek-flash`，thinking 关闭 |
| 运行 | `npm run dev` 开发 / `npm start` 日常，开机自启 |

**不用**：Docker、Supabase、NextAuth、Redis、任何云服务。

### 8.2 备份

每天 02:00 复制 `data/app.db` 到 `data/backup/YYYYMMDD.db`，留 14 份。一个 node 脚本 + 计划任务。

### 8.3 手机上的补救：ics 导出

电脑关机手机就打不开——这是单机方案的硬伤。但**最需要在手机上看的是固定事件**（几点开会、几点上课），不是队列。

所以：`/api/export.ics` 把所有 `is_fixed` 事件导成 ics，一次性导入手机系统日历。

职责天然分开：**手机看"什么时候有事"，电脑看"现在做什么"。** 零成本，且比做同步服务靠谱。这一项放 V0.1.1，不占首版工期。

## 九、AI 选型

**`deepseek-flash` 就是当前最优解，不换。**

1. 用新名 `deepseek-flash`（V4.1-Flash）；旧的 `deepseek-v4-flash` 只是路由过去，早晚会废
2. **解析和排序都关掉 thinking**。默认是开的，对这两类任务只会更慢更贵更飘（思考模式下 temperature 无效）。质量不够再单独给排序开 `reasoning_effort: low`
3. 长而固定的 system prompt 放消息最前，任务池放后面 —— 命中缓存后输入约便宜 98%
4. 不混用多家

用量一个月个位数人民币，不值得做任何成本优化。

## 十、V0.1 范围（七件事，10–12 天）

1. 单输入框，多行 = 多条，回车即提交
2. `/api/parse`：自动区分固定事件 / 软任务；失败存原文，不报错
3. `/api/rank`：AI 全局定序 + 每条的 20 字理由
4. **时间流视图**：硬块 + 空档 + 队列 + 尽力线 + 预计收工
5. 四象限视图（只读 + 拖拽改分类）
6. 拖拽：软任务改序、硬事件改时间；完成 / 顺延 / 重排
7. 最简重复（weekly）+ 全天事件 + 每日备份

**V0.1.1**：ics 导出、daily 重复、估时校准
**V0.2**：周视图、每周复盘（象限分布 / 完成率）、夜间清洗

**不做**：团队协作、甘特图、日历双向同步、语音、聊天式助手、主题皮肤、PWA 安装

## 十一、风险

1. **排序人格漂移** → 四道闸第 4 道，别省
2. **AI 让 Q1 挤掉 Q2** → "Q2 每天保底一个位置"写成 `prefs` 里的硬规则，由代码执行，不是求 AI 记得
3. **固定/软任务判定错** → 卡片上一键切换，别追求解析准确率
4. **手机关机就看不到** → ics 导出（8.3）
5. **免费输入导致任务爆炸** → 尽力线就是刹车
6. **单一模型依赖** → 三层退化，不是算法兜底
